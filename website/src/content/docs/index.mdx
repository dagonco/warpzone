You have a home server full of ROMs and more than one console to play them on. Each one has its own copy of the games, its own idea of which games it wants and its own saves. warpzone is a thin layer of conventions and automation on top of [Syncthing](https://syncthing.net) that makes the server, called **the hub**, the single source of truth. Syncthing does all the transfer between machines; warpzone configures it, files new games into the hub's library and removes from a device what its whitelist no longer allows.

## The problem

- Copying a 2 TB library to a 512 GB device means picking games by hand, every time.
- Editing a "what do I want here" list on each device, over SSH or with a gamepad, does not scale past one device.
- Saves live in a dozen emulator-specific places, and syncing them naively syncs the wrong things.
- One accidental delete on a console should never reach the server.

warpzone fixes this with three rules: the hub owns the library, devices only receive it, and each device chooses what it gets with a **whitelist that is edited only on the hub**.

## How it works

```
                       hub (home server)
         +-----------------------------------+
         | library/   roms, bios, extras     | --> whitelisted, receive-only
         | songs/     Clone Hero, YARG       | --> whitelisted, receive-only
         | tools/     scripts, docs          | --> receive-only
         | saves/     per emulator           | <-> two-way, 30 days of history
         | frontend/  ES-DE media, gamelists | <-> two-way
         | settings/  emulator settings      | <-> two-way, 30 days of history
         | inbox/     new dumps (not synced) |
         +-----------------------------------+
                 | Syncthing           |
                 v                     v
            console A              console B   ...
        (patterns-<device>)    (patterns-<device>)
```

Each `library/` and `songs/` folder on the hub holds one `patterns-<device>.stignore` per device. A device applies only its own, so the same folder gives each console a different slice of the library. Saves get their own two-way folders, so their direction can never leak into the library. New games arrive through the `inbox/` folder, which is never synced: you drop dumps there, and `warpzone inbox` identifies, converts and files them.

## What you need

- [Syncthing](https://syncthing.net) v2.x on the hub and on every device.
- Python 3.11 or newer on the machines that run `warpzone`. Standard library only: no packages to install.
- The hub is driven remotely through its Syncthing REST API, so it does not need Python.

## Legal

warpzone ships and locates no ROMs, BIOS files, keys or firmware, and never will. `warpzone bios` and `warpzone inbox` only compare what you already have with public file names, sizes and hashes. It only moves files you already have between machines you own. Use your own legally obtained dumps.
